# 研究问题与边界

## 来源与数学子问题

本项目选择《HarmonyOS难题发布-第七期》难题 1“基于非线性优化的众包离线高精度位置聚合”。帮助设备给出报告位置 `l_i`、BLE RSSI `r_i` 和允许的可靠性代理，目标是在二维平面估计一个离线设备的静态位置。

\[
\hat{x}=\arg\min_x\sum_i\omega_i\left(f(r_i)-\|x-l_i\|_2\right)^2.
\]

这是加权平方损失的基础模型。当前 Huber/Cauchy 实现将 `sqrt(w_i)` 乘残差后交给鲁棒损失，不能普遍写成权重乘在鲁棒损失外面。adaptive 才交替更新坐标与残差可靠性权重，并可乘元数据、时间稳定性权重；最后固定权重重解，使返回坐标和权重一致。这些是既有方法的实现与比较，不是提出新定位算法或证明模型选参最优。

## 当前可验证范围

本中期用固定 seed 的合成场景比较 NLS、weighted NLS、Huber、Cauchy、adaptive 和 adaptive+temporal，污染包括测距噪声、NLOS 正偏异常、帮助设备报告位置漂移、聚簇/共线几何以及 RSSI 校准偏差。目标在每个 trial 内不运动；帮助设备移动标签和重复测距不稳定度并非目标运动标签。

observable 的精度、年龄是与污染标签独立的合成代理，仍非真实设备质量；oracle 元数据不能用于 Agent 调参。真值保留在评价端，求解器与提案模型不接收目标真值。`mobile_detection` 是历史指标名，不应将其 F1 解释为移动目标检测性能。

真实 run `deepseek-midterm-20261116` 进行了 4 轮候选评估，第 5 轮 3 个无效提案被阻断，日志共保存 8 次 DeepSeek 响应。最终 selected 是 **Huber+temporal**，不是 adaptive；holdout CEP90 为 11.6754m，对照 NLS 为 19.4654m。普通配对百分位 bootstrap 只覆盖固定合成场景混合内的不确定性；失败率差的区间跨零，不确认该项收益。完整数据与规则见 [实验协议](experiment_protocol.md)。

已有 run 可以从源实验核对完整条件、trial 配对和冻结后时间顺序，但后补 snapshot/hash 只能称事后核验，不是事前登记。新 run 应先完整登记配置和生成器 hash，冻结后仅补缺失产物且不再调参。

## 不作出的声明

本项目不声称解决 Huawei 生产系统，不将合成静态二维结果外推为真实工业 BLE 表现，不声称实现移动目标检测或目标轨迹估计，也不以仿真 CEP90 低于 30m 作为原题 KPI 达标证据。原题的真实 CEP90 和移动检测目标必须在官方数据与协议下复测。

智能体价值当前体现为受限提案、验证反馈、规则决策和审计闭环；模型理由是待检验假设，不是数学或因果证明。没有等预算网格、随机和本地诊断对照，不能宣称 LLM 搜索更优。真实标定、设备异构、楼层地图、延迟、授权脱敏数据及新场景泛化仍属于后续工作。
