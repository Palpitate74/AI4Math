## 0:00–0:40｜选题与证据范围（第 1 页）

“这门课要求开发一个智能体，用它研究并迭代应用数学问题。我选择《HarmonyOS难题发布-第七期》难题 1 中的 BLE 众包离线位置聚合：由多个帮助设备的报告位置和 RSSI，估计一个离线设备的位置。

## 0:40–1:20｜数学模型与实现（第 2 页）

“令帮助设备报告位置为 l_i，RSSI 转换距离为 d_i，残差为 norm(x−l_i)−d_i。NLS 使用平方损失，加权 NLS 使用元数据权重，Huber/Cauchy 降低大加权残差的影响。实际优化器接收 sqrt(w_i) 乘残差，所以鲁棒损失作用于加权残差，不应简单写成把权重乘在鲁棒损失外面。

adaptive 才是坐标和可靠性权重交替更新；Huber/Cauchy 不能都笼统叫 IRLS。最后一次权重更新后再固定权重求解，使返回坐标与返回权重一致。各方法用相同的报告坐标均值初始化，不把真值送给求解器；RSSI 校准偏差以 dBm 只施加一次。

这些是实现机制与修复，不是新算法证明。数值 success 也不等于正确定位，启发式 confidence_radius 不是经过校准的置信区域。”

本 run 验证为六场景各 48 trials，共 288；holdout 为相同六类场景各 64，共 384。seed 分别为 41001–41006 和 51001–51006，没有重叠。observable 元数据是独立于污染标签的合成代理，不是真实传感器质量，oracle 不参与调参。

冻结时间为 2026-11-16 04:33:07.518450 UTC，七个 holdout 实验记录均在之后。已有实验可事后核对场景完整配置、配对 trial 和时间顺序，但这个历史 run 原本没有完整事前 snapshot 与生成器 hash 登记链。后补 snapshot 只能叫事后核验，不能追溯成事前登记。新 run 才应在实验前完整冻结配置与 hash；冻结后恢复只补缺失，不重跑、不调参。”

## 2:05–2:45｜验证消融与最终配置（第 4 页）

“验证 NLS 的 CEP90 为 23.6614 米，中位误差 6.6505 米，>30 米失败率 8.6806%。实际消融有 weighted NLS、Huber、Cauchy、adaptive、adaptive+temporal，表格只列真实实验。

最终选的是 Huber+temporal，尺度 8 米、可靠性阈值 0.2、max_irls_iterations=10，temporal=true。该 IRLS 字段对当前 Huber 不是实际迭代调参杠杆。最终验证 CEP90 为 12.4578 米，中位误差 3.1801 米，失败率 4.5139%。它来自 Agent 第 1 和第 4 轮的采纳，不是看完消融或 holdout 后偷偷挑最优。

这些是验证集成绩，不是测试结论。共线等退化几何切片仍有长尾，不能让总体百分位掩盖困难场景。”

## 2:45–3:30｜实际四轮评估与第五轮阻断（第 5–6 页）

“第 1 轮从 NLS 改为 Huber，验证 CEP90 从 23.6614 降到 12.5395 米，并通过中位误差、失败率、clean 切片和数值收敛护栏，所以采纳。

第 2 轮提出尺度从 8 缩到 6，模型预计尾部更好，但实际 CEP90 升至 12.8103 米，所以拒绝。第 3 轮改 Cauchy，虽然中位误差更低，CEP90 却到 13.1363 米，仍被拒绝。这正说明模型理由不是证明，实验可以推翻预期。

第 4 轮先返回一个 schema 无效提案，重试后合法开启 temporal，CEP90 小幅降到 12.4578 米，因此采纳。这个 0.0817 米验证变化不能单独宣传为统计显著。

第 5 轮连续 3 次提出 max_irls_iterations=14，对当前 Huber 不适用而被阻断，proposal 和候选 ID 为空。日志的 1+1+1+2+3 共 8 次响应都有 deepseek-chat、response_id、midterm-v2.1、usage 和耗时；合法候选评估只有前四轮。”

## 追问时的边界

若被问是否达到 Huawei KPI，应答“这里只是固定合成静态二维实验，未作真实工业验收声明”。若问是否检测移动目标，应答“没有，mobile_detection 是帮助设备不稳定度的旧指标名”。若问是否新算法，应说明是 NLS、Huber/Cauchy、自适应权重与 Agent 编排的实验研究，不把模型文字理由当推导或证明。

若问为何有 5 轮却只评估 4 次，应说明轮次记账包含错误：第 5 轮 3 个无效提案全部被阻断，没有候选实验；8 次响应含第 4 轮重试与第 5 轮失败。若问是否提前完整登记，应说明已有 run 只能事后核验，不能因后来补了 snapshot 就称原先完整事前登记。

若问 CI 能否推广，应说明它条件于固定六场景混合；失败率差的区间跨零，不能把较低点估计直接包装成确定收益。若问模型是否比网格有效，应说明没有等预算对照，当前证据只支持它执行了可审计的受限提案闭环。
